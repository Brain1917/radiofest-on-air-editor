# Внутренний цикл качества

Пользователь не запускает эти стадии. Скилл ведёт их внутренне и показывает журнал только по просьбе.

| Стадия | Вход | Обязательный результат | Выходной критерий | Возврат |
| --- | --- | --- | --- | --- |
| Discuss | Просьба, материалы, доступный контекст. | Цель, ветка, ограничения, блокирующие пробелы. | Все материалы прочитаны; задан не более чем один текущий блокирующий вопрос. | Остаётся в Discuss до ответа либо выпускает частичный результат со статусом проверки. |
| Spec | Результат Discuss. | Выбранный формат, критерии, обязательные источники, применимые риски. | Каждый критерий наблюдаем; неизвестное помечено. | Discuss, если неясна цель или источник. |
| Plan | Spec и M1-M11. | Реестр цепочки, действия и проверки, связанные с критериями. | Для каждого обязательного звена есть действие и способ проверки. | Spec, если действие не связано с критерием. |
| Implement | Утверждённый внутренний Plan. | Черновик трёх блоков и доказательства преобразований. | Все запланированные действия выполнены либо имеют блокер. | Plan или более ранняя стадия по причине. |
| Verify | Черновик, исходники, Spec и Plan. | Протокол соответствия фактам, формату, времени и цепочке. | Каждый критерий имеет PASS/FAIL и доказательство. | Самая ранняя стадия, которая устраняет FAIL. |
| Review | Проверенный черновик. | Отдельный поиск пропусков, противоречий и неподтверждённых утверждений. | Нет необработанного замечания; критические замечания блокируют переход. | Самая ранняя стадия причины замечания. |
| Judge | Spec, Plan, Verify и Review. | Только `PASS` или `FAIL` со ссылками на доказательства. | PASS разрешён только при закрытых обязательных критериях и отсутствии блокеров. | Стадия самой ранней причины FAIL. |
| Done | Judge PASS и мастер-версия. | Финальный пакет и обновлённая память задачи. | Конкретный `version_id` сохранён; статус не превышает доступный человеческий допуск. | Недоступен без Judge PASS. |

## Правила возврата

- Ошибка источника возвращает к Discuss или Spec.
- Ошибка состава проверки возвращает к Plan.
- Ошибка текста возвращает к Implement.
- Пропуск проверки возвращает к Verify.
- Новое независимое замечание возвращает к его фактической причине, а не только к Review.

## Разделение ролей

Implement создаёт результат. Verify сверяет его с утверждёнными критериями. Review ищет пропуски независимо от списка исполнителя. Judge оценивает доказательства и не исправляет текст сам.

Если среда не поддерживает отдельные контексты, выполняй стадии отдельными закрытыми проходами. Не называй такой Review независимым. В журнале укажи фактический способ проверки.

## Done guard

Перед Done проверь одновременно:

- Judge вернул точное значение PASS.
- В `chain_state` нет `blocked` для обязательного или сработавшего условного звена.
- `earliest_blocker` равен `null`.
- Паспорт содержит непустые `version_id`, `updated_at` и `approver` для статуса не ниже `готово к допуску`.
- Человеческий допуск содержит совпадающие `approver` и `approval_confirmed_by`, точный `approval_confirmed_version` и время `approval_confirmed_at`.

Без этих условий задача остаётся в работе или получает статус `требуется проверка`.
