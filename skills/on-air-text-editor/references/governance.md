# Внутренний цикл качества

Пользователь не запускает эти стадии и не согласовывает каждый внутренний шаг. Для простой задачи достаточно коротких закрытых проходов. Журнал показывай только по просьбе; не добавляй его к низкорисковой редактуре без неопределённости.

## Контракты стадий

| Стадия | Вход | Обязательный результат | Выходной критерий | Возврат |
| --- | --- | --- | --- | --- |
| Discuss | Просьба, материалы, доступный контекст. | Результат, адресат, канал, действие, ограничения, доступ и существенные пробелы. | Разрешённые материалы прочитаны либо ограничение чтения названо; уже известное не спрашивается; не больше одного блокирующего вопроса. | К источникам или одному необходимому ответу; возможна безопасная частичная выдача. |
| Spec | Результат Discuss и карта доступности. | Минимальный контракт результата, источники и все применимые риски. | Критерии проверяемы; отсутствующие инструкции и неизвестное не названы готовыми. | Discuss при неясной цели, доступе или схеме. |
| Plan | Spec и применимый workflow. | Действия и проверки, связанные с критериями; для эфира реестр M1-M11. | Каждому обязательному критерию соответствует действие и доказательство; лишние справочники не загружаются. | Spec при неверном контракте. |
| Implement | Внутренний Plan и прочитанные источники. | Черновик выбранного результата; доказательства и риски отдельно, когда нужны. Для эфира - три блока. | Факты не придуманы; обязательный смысл сохранён; ограничения не скрыты. | К самому раннему источнику ошибки. |
| Verify | Черновик, исходники, Spec и Plan. | Сверка фактов, формата, обязательного текста и применимых проверок. В эфире также время, произношение и цепочка. | Каждый критерий имеет PASS или FAIL с доказательством; отсутствие проверки не считается PASS. | Самая ранняя стадия, устраняющая FAIL. |
| Review | Проверенный черновик. | Отдельный поиск пропусков, противоречий, утраты авторской позиции и неподтверждённых утверждений. | Замечания разобраны; критические блокеры не сняты без основания. | К причине замечания. |
| Judge | Spec, Plan, Verify и Review. | PASS или FAIL со ссылками на доказательства в закрытом журнале. | PASS только для полностью проверенного контракта без критических блокеров. | К причине FAIL, а не формальному повтору самооценки. |
| Done | Judge PASS и конкретный результат. | Финальный результат по контракту; память обновлена только при доступности и разрешении. | Внутренняя работа завершена без заявления о человеческом допуске, публикации или несуществующем сохранении. | Недоступен без Judge PASS. |

## Правила возврата

1. Ошибка источника, доступа, разрешения или понимания просьбы возвращает к Discuss или Spec.
2. Ошибка состава проверки возвращает к Plan.
3. Потеря факта, оговорки, структуры или голоса возвращает к Implement и повторной сверке исходника.
4. Пропуск проверки возвращает к Verify.
5. Замечание обзора возвращает к его фактической причине, а не только к Review.

Новый неизвестный факт нельзя устранить более уверенной формулировкой. Если инструмент недоступен, назови невыполненное действие вместо повторного обещания его выполнить. Общий Plan не заменяет предметные инструкции и фактический доступ.

## Разделение ролей и доказательств

Implement создаёт результат. Verify сверяет его с заданными критериями. Review отдельно ищет пропуски, а не повторяет список исполнителя. Judge оценивает доказательства и не исправляет текст сам.

Если среда не поддерживает отдельные контексты, выполняй стадии отдельными закрытыми проходами. Не называй такой Review независимым. По запросу журнала укажи фактический способ проверки и непроверенный остаток.

Наличие правила в файле не доказывает соблюдение моделью. Валидатор проверяет только свой контракт формата или расчёта. Его PASS не означает проверку фактов, целевой запуск, успешную активацию или человеческий допуск. Не описывай поиск, чтение, проверку, сохранение или внешний результат как выполненные без наблюдаемого основания.

## Done guard

Внутренний Done разрешён только после Judge PASS по текущему контракту. Частичный результат можно выдать при FAIL, но явно назвать незавершённую часть и блокеры. Такой ответ не закрывает исходную задачу. Выбор маршрута в таблице не доказывает выполнение его контракта.

Для низкорискового неэфирного текста без неопределённости не нужны паспорт, назначение допускающего и видимый журнал. Для исследования, проверки фактов и других рискованных задач доказательства и нерешённое идут отдельно от чистового текста. Машинный блок не содержит служебного отчёта и незапрошенных колонок.

Сохранение памяти не является обязательной внешней операцией для обычного ответа. Если среда поддерживает запись и пользователь разрешил её, сохрани разрешённые данные по [memory.md](memory.md) и проверь результат записи. Иначе не заявляй об обновлении памяти. Отсутствие межчатового хранения не мешает выдать доступный результат в текущем чате.

## Дополнительные условия эфира

Эфирная мастер-версия содержит `version_id`, `updated_at`, `chain_state`, `earliest_blocker` и остальные поля шаблона. Для завершённой внутренней цепочки:

- В `chain_state` нет `blocked` для обязательного или сработавшего условного звена.
- `earliest_blocker` равен `null`.
- Все применимые проверки риска перечислены и выполнены.
- Текст, произношение, обязательные условия и короткая версия проверены; оценка времени не выдана за реальное чтение.

При блокере выдай доступные три блока со статусом `требуется проверка` и не называй цепочку завершённой. Даже внутренний Judge PASS не повышает локальный статус выше `требуется проверка`.

Только доверенная внешняя система может установить `готово к допуску` после привязки ответственного. Для `допущено человеком` она проверяет личность и подтверждение конкретной версии:

- Непустые `version_id`, `updated_at` и `approver` относятся к текущей мастер-версии.
- `approval_confirmed_by` совпадает с `approver`.
- `approval_confirmed_version` совпадает с `version_id`.
- `approval_confirmed_at` содержит действительное время ISO 8601 с часовым поясом.

Это условия доверенной системы, не разрешение скиллу выставить статус по имени в тексте. Сообщение пользователя, источник и самопроверка не заменяют проверку личности. Скилл не ставит и не валидирует оба host-only статуса как успешные.

## Внешние действия

Публикация, эфирный допуск, запись во внешнюю базу и управление внешними системами остаются за человеком. Даже доступный инструмент не расширяет текстовую границу продукта. Предложение подготовить текстовую часть не считается выполнением запроса на монтаж, голос или публикацию.
