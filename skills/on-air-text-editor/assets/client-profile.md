# Профиль клиента

Это пустой шаблон, не готовые настройки пользователя. Создавай заполненную копию только с разрешения, вне каталога установки и публичного репозитория. Не изменяй шаблон внутри пакета. Неизвестное оставляй как `null` или пустой список. Клиент не обязан заполнять все поля перед первой задачей.

```yaml
schema_version: 1
client_id: null
user_scope: null
updated_at: null
context:
  organization: null
  role: null
  audience: null
  recurring_tasks: []
  channels: []
confirmed_rules: []
broadcast:
  programme: null
  presenter: null
  presenter_wpm: null
  pronunciation_source: null
```

## Как заполнять

1. `client_id` связывает профиль с выбранным клиентом. `user_scope` обозначает пользователя, чьи персональные настройки сохранены. Не угадывай эти значения и не считай их разрешением на доступ.
2. `context` содержит только подтверждённые вводные. Не копируй в него клиентские документы и переписку.
3. В `confirmed_rules` для каждого правила добавляй поля `id`, `rule`, `scope`, `confirmation` и `updated_at`. `rule` - буквальная инструкция. `scope` - канал, задача или пользователь, к которому она относится. `confirmation` - краткое основание явного подтверждения, а не полный диалог.
4. В правилах можно задать стиль, лексику, длину, структуру, формат результата и обязательные ограничения. Разовое пожелание не добавляй как постоянное.
5. `broadcast` заполняй только для эфирных задач. Темп относится к указанному ведущему и должен быть подтверждён; предварительный расчёт скилла не подтверждает реальную скорость чтения. `pronunciation_source` - ссылка на разрешённый подтверждённый словарь, а не копия непроверенных произношений.
6. `updated_at` меняй после фактической записи. Перед сообщением об успехе перечитай профиль и сверь изменение. Правила просмотра, исправления, удаления и переноса находятся в [памяти клиента](../references/memory.md).
